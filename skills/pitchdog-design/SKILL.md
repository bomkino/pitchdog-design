# pitch.dog Design

Design with a spine, not a uniform. Make the artifact useful, specific, alive, and visibly cared for; stop before the frame eclipses its subject.

## Resolve authority

Apply this order when instructions conflict:

1. Safety, consent, privacy, law, accessibility, and authorization.
2. Explicit current user constraints and protected material.
3. Current target-brand authority and owner-approved decisions.
4. Audience outcome, content truth, proof, and medium.
5. This skill's judgment and pitch.dog foundation.
6. References, patterns, trends, and optional polish.

Newer owner-confirmed decisions outrank installed profiles and old artifacts. Keep accepted copy, facts, names, pronouns, titles, quotes, figures, URLs, credits, rights, and permissions unchanged unless the user authorizes a change.

## Choose the branch

- **Brand Mode:** a pitch.dog-owned artifact or explicit pitch.dog branding request. Read [profile routing](references/profile-routing.md), [brand foundation](references/pitchdog-brand-foundation.md), [typography authority](references/typography-authority.md), and only the medium branch needed.
- **Mindset Mode:** a client, creator, external brand, or personal artifact. Read [profile routing](references/profile-routing.md) and [external-brand adapter](references/external-brand-adapter.md). Transfer judgment, not pitch.dog's clothes.
- **Review or refine:** preserve the existing brand and accepted direction unless translation is requested. Diagnose before changing.

Ask at most one strategic question only when the wrong audience, profile, action, or authority would materially change the result and no responsible default exists. Otherwise state consequential assumptions briefly and proceed.

## Run the process

### 1. Establish the real job

Identify audience, context, desired understanding or action, available proof, protected material, permissions, medium, and the costliest polished false success. Write one governing idea and two or three creative dials.

**Complete when:** the job can be stated without a style adjective and success has artifact-level evidence. Use [Actual Goal and soul](references/actual-goal-and-soul.md) when the work is consequential or style threatens to replace purpose.

### 2. Build the argument or task spine

Give every page, state, spread, slide, or frame one job. Put proof near the claim it earns. In an authored editorial scene, decide the primary event, the quiet secondary event if one is needed, and what stays still. In a dense operational surface, establish one clear task and hierarchy rather than forcing one visual event.

**Complete when:** hierarchy and sequence work in a static, low-colour view before effects or motion.

### 3. Author the direction

Use one subject-native visual thesis. Share foundations and behaviour; keep narrative compositions authored. Let typography, space, colour, material, proof, and interaction serve the same idea.

For pitch.dog websites, read [website design language](references/website-design-language.md). For new digital work, read [digital theme and icons](references/digital-theme-and-icons.md). Whenever the work creates or changes a surface, read [colour and material](references/colour-and-material.md); its no-additive-grain boundary applies in every profile and medium.

**Complete when:** the direction would become meaningfully wrong if transplanted unchanged to another subject.

### 4. Build through native systems

Prefer the target platform's semantic structure, layout, type roles, tokens, components, states, and interaction primitives. Extract a shared component only when repeated authority, accessibility, data, or behaviour earns it. Never start by filling a component catalogue.

**Complete when:** the representative parent artifact works and each shared primitive has at least one real second use.

### 5. Author relevant adaptations

For new digital work, author Light, Dark, and System-default states. Also edit phone, tablet, wide, reduced motion, loading, empty, partial, error, success, permission, and recovery states where the medium makes them relevant. Translate meaning across media; do not paste geometry.

**Complete when:** each required context preserves priority, proof, operation, and authorship without depending on another context.

### 6. Inspect the artifact

Review the real output, not only source, a screenshot, a build log, or a producer claim. Use the smallest discriminating checks from [artifact review](references/artifact-review.md), repair the highest-consequence failure, and rerun affected checks plus one regression pass.

**Complete when:** the artifact does its real job; material risks are resolved or named; and another change would be decorative churn. Only the owner can accept consequential creative work.

## Hold the constitution

- Idea before decoration; proof before broad claims.
- One sovereign subject and one dominant event per authored scene; dense task surfaces use clear hierarchy instead.
- Empty space must create pressure, pace, relief, or value.
- Typography comes from the active brand authority, never convenient invention.
- Colour behaves as atmosphere, proof field, signal, or state—not a section carousel.
- Material presence comes from real edges, crops, contact, marks, and evidence.
- Motion explains causality, feedback, or continuity; stillness is a first-class state.
- Phone is an authored edit, not stacked desktop.
- Familiar patterns are welcome when they reduce labour or error.
- Wit is one semantic turn, not a component system.
- Credits, privacy, recovery, access, ordinary-device performance, and maintainability are design decisions.
- Keep edited, built, rendered, checked, installed, deployed, published, live, and accepted distinct.

## Design motion deliberately

Decide in this order: frequency, purpose, behaviour, origin, access, evidence. Remove motion from high-frequency keyboard actions. Use exact-property CSS transitions or WAAPI for predetermined UI states; use a velocity-aware spring only for gesture-driven, momentum-carrying, interruptible motion. Start from the live presentation value, preserve input, reverse cleanly, and provide a complete reduced-motion state.

## Produce useful outputs

- **Brief:** audience outcome, proof, visual thesis, spine, profile, material decisions, responsive/access requirements, and acceptance evidence. Use the [design brief template](templates/design-brief.md) when durability helps.
- **Motion contract:** purpose, states, trigger, physical verb, live-value behaviour, interruption, reversal, terminal state, reduced motion, and performance ceiling. Use the [motion contract template](templates/motion-contract.md).
- **Review:** objective verdict, evidence that works, proxy-compliant failures, consequential unknowns, ranked repairs, exact checks performed/not performed, and separate edited/built/rendered/installed/deployed/published/live/accepted states as relevant. For UI code, put all actionable changes in one `Before | After | Why` table. Use the [artifact review template](templates/artifact-review.md).
- **Brand profile:** use the canonical [pitch.dog profile](brand-profiles/pitchdog.yaml) only in Brand Mode. Derive another brand from evidence with the [brand profile template](templates/brand-profile.yaml).

Stop when the result holds. If truth, assets, authority, access, or acceptance is missing, preserve the unknown and name the exact gate.
